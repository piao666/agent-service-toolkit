# Enterprise Prompt Guidelines

企业知识库 Agent 的 Prompt 设计应分层处理，而不是把所有要求写进一个系统提示。Query rewrite prompt 的目标是提升检索召回，它需要保留用户原意，补充业务关键词，删除无关寒暄，并把模糊问题改写为更适合向量检索的短查询。改写后的查询不应添加文档中不存在的事实，也不应把问题扩展到无关主题。

Answer synthesis prompt 的目标是生成可靠答案。它应明确要求模型优先使用检索上下文回答，并在上下文不足时说明无法从当前知识库确认。对于流程类问题，答案应按步骤组织；对于解释类问题，答案应先给结论，再说明原因；对于对比类问题，答案应列出差异点和适用场景。回答中应避免引用外部知识来填补缺失证据。

Fallback prompt 用于处理无命中、低置信度、模型超时或工具异常。fallback 不应伪造答案，也不应笼统说系统错误。更好的表达是说明当前知识库没有找到足够证据，并给出下一步建议，例如补充关键词、确认文档是否已入库、或让管理员补充相关知识材料。这样可以让系统失败时仍然可解释。

Prompt 调试需要结合 retrieval debug。若命中 source 正确但回答偏离，通常是 answer synthesis prompt 约束不够；若命中 source 错误，可能是 query rewrite 或 chunk 粒度问题；若无命中，可能是知识库缺少文档、embedding 不适合当前语言、top_k 太小或用户问题过于模糊。Prompt 的价值不只是让回答更好看，而是让 Agent 在不同失败场景中更可控。
