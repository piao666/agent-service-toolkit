企业知识库 Agent + RAG 后端服务升级项目 - task.txt
====================================================

项目目标
--------
基于 upstream `agent-service-toolkit` 进行二次开发，将原有 FastAPI + LangGraph 多 Agent 服务框架升级为可复现、可调试、可评估的企业知识库 Agent + RAG 后端服务。

项目主线是后端工程化升级，不是训练或微调大模型。最终交付应覆盖：

- 企业知识库专用 RAG Agent：`enterprise-rag-agent`
- 统一业务查询接口：`/enterprise/agent/query`
- 本地 embedding 默认路线
- Chroma 向量库与 collection：`enterprise_knowledge_base`
- source tracing 与 retrieval debug
- DeepSeek 与 Qwen/OpenAI-compatible provider 接入验证
- QA 评估、bad case 分析、接口文档、架构图和面试材料

技术路线
--------
- 后端框架：保留 FastAPI 服务入口与现有路由模式。
- Agent 编排：基于 LangGraph，新增企业知识库 RAG Agent。
- Agent 注册：通过 `src/agents/agents.py` registry 接入 `enterprise-rag-agent`。
- RAG 模块：新增 `src/rag/`，避免把企业知识库逻辑继续堆到上游示例工具里。
- Retriever Tool：新增 `src/agents/enterprise_tools.py`，返回 source、score、chunk_id、metadata、content_preview。
- Agent 文件：新增 `src/agents/enterprise_rag_agent.py`。
- 向量库：Chroma，本地 persist，collection 使用 `enterprise_knowledge_base`。
- 文档目录：`docs/enterprise_rag_backend/`。
- 默认 chunk 参数：`chunk_size=800`、`chunk_overlap=120`、`top_k=5`，后续通过配置调整。
- 数据流：document -> chunk -> embedding -> vector store -> retrieval -> context -> answer。

模型 provider 策略
------------------
- DeepSeek：用于本地开发、Prompt 调试、中文问答验证和 baseline。
- Qwen/OpenAI-compatible：用于私有化、本地或 HPC 推理服务接入验证。
- OpenAI-compatible 在本项目中表示接口协议兼容，不代表必须配置国外 API。
- 不要求配置 OpenAI、Google、Anthropic、Groq 等 provider 作为主线。
- 保留 upstream 多 provider 支持，但项目文档和验收只围绕 DeepSeek + Qwen/OpenAI-compatible。
- 本项目不做训练主线；如接入 vLLM Qwen endpoint，只记录为推理服务。

    MRR, keyword hit, and latency.

    Markdown, JSON/YAML, table-like data, and code/API documentation.

  - Rerun `/enterprise/agent/query` only after the local service and provider are available.
  - Record skipped, failed, or passed honestly.
  - Separate retrieval success, model generation success, source citation success,
    and answer quality.

Phase 6E sub-phases:
- Memory requirement analysis.
  - Clarify why full-history prompting is insufficient and risky.
- Short-term memory.
  - Keep recent turns for reference resolution and short context follow-up.
- Summary memory.
  - Compress older context while tracking summary drift risk.
- Persistent memory.
  - Design durable user or task memory with privacy and deletion boundaries.
- Retrieval memory.
  - Evaluate retrieving relevant conversation history without cross-session leakage.
- Memory policy.
  - Define what to remember, what not to remember, expiration, consent, deletion,
    and tenant/user/session isolation.
- Multi-turn memory evaluation.
  - Evaluate reference resolution, corrections, topic switching, noise filtering,
    sensitive information handling, and token cost.

Phase 6F sub-phases:
- Incremental indexing.
  - Plan document versioning, chunk hash tracking, upsert/delete, and stale chunk cleanup.
- Multi-tenant and permission control.
  - Plan tenant, department, role, ACL, metadata filter, permission check, and audit log.
- Performance and cost control.
  - Plan query cache, embedding cache, batching, async retrieval, timeout/retry,
    top-k control, and provider cost budget.
- Risk control and security.
  - Plan prompt injection checks, sensitive query handling, source leakage guard,
    refusal/fallback policy, audit logs, and red-team cases.
- Provider routing and failover.
  - Plan provider health checks, timeout policy, retry policy, cost-aware routing,
    quality-aware routing, local fallback, and vendor failover.
- Observability and feedback.
  - Plan trace id, query log, retrieval log, source hit log, latency log,
    fallback log, user feedback, and bad-case feedback loop.
