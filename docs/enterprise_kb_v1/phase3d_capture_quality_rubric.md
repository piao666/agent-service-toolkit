# Phase 3D 采集质量判分标准

> 版本: v1-draft | 状态: draft | 最后更新: 2026-07-04

---

## 一、概述

本判分标准用于 Phase 3E 正式执行采集后评估双通道质量。每条样本独立评分，总分决定该样本是否通过。

评分：每项 1-5 分（1=严重缺陷，5=优秀），各维度平均值 ≥3 分为通过。

---

## 二、Text/DOM 采集质量（权重 50%）

### T1 — 标题层级保留（score 1-5）
- 5: 全部 H1-H4 完整，无丢失/错位
- 3: 超过 80% 标题保留，个别 H4 丢失
- 1: 标题丢失 >30% 或层级混乱

### T2 — 正文完整性（score 1-5）
- 5: 全部段落完整，无截断
- 3: 部分段落裁剪但语义可恢复
- 1: 大段内容缺失

### T3 — 代码块完整性（score 1-5）
- 5: 所有代码块完整，含 import、函数签名、关键逻辑
- 3: 代码块完整但部分内联注释丢失
- 1: 代码块截断或丢失 >30%

### T4 — 表格 Markdown 正确性（score 1-5）
- 5: 所有表格列对列正确，表头保留
- 3: 表格可读但个别列宽错位
- 1: 表格不可解析或行列混乱

### T5 — 列表/步骤顺序保留（score 1-5）
- 5: 有序/无序列表完全保留原始顺序
- 3: 列表保留但层级缩进部分丢失
- 1: 列表变为连续文本

### T6 — 链接与锚点保留（score 1-5）
- 5: 所有文档内链接和跨页链接保留
- 3: 内链保留但锚点跳转失效
- 1: 链接全丢失

### T7 — 页面噪声控制（score 1-5）
- 5: 侧边栏/导航/页脚全移除，只保留正文
- 3: 少量导航残留但不影响正文阅读
- 1: 导航/广告大量混入正文

**Text/DOM 通过**：7 项平均分 ≥3.0

---

## 三、Visual Screenshot 质量（权重 30%）

### V1 — 全页覆盖（score 1-5）
- 5: 截图从页面顶部到底部完整覆盖
- 3: 截图中断 1-2 处但可拼接
- 1: 大面积截断

### V2 — Tile 编号稳定性（score 1-5）
- 5: 全部 tile 有稳定编号 {sample_id}_tile_{N}.png，可唯一回溯
- 3: 部分 tile 编号不连续但可推断
- 1: tile 无编号或完全混杂

### V3 — 表格/代码/图示可见性（score 1-5）
- 5: 表格线、代码缩进、图示线条在截图中清晰
- 3: 可见但模糊，不便直接引用
- 1: 不可辨认

### V4 — 布局完整性（score 1-5）
- 5: 页面并排布局（代码+注释）在截图中完整可见
- 3: 部分布局因 tile 切分而断裂
- 1: 切分破坏了页面布局理解

### V5 — 干扰排除（score 1-5）
- 5: 无 cookie 弹窗、浮层、广告遮挡
- 3: 有浮层但仅在顶部 tile 不可见区域
- 1: 核心内容被遮挡

**Visual 通过**：5 项平均分 ≥3.0

---

## 四、Cross-channel 对齐质量（权重 15%）

### C1 — chunk→tile 映射（score 1-5）
- 5: 每个 text chunk 可映射到对应 tile
- 3: 映射成立但粒度粗（≥3 chunk 映射到同一 tile）
- 1: 无法建立映射

### C2 — metadata 一致性（score 1-5）
- 5: text 和 visual metadata 中 source_id / url / capture_time 完全一致
- 3: 个别字段不同但不影响追溯
- 1: metadata 不一致导致无法溯源

### C3 — 可追溯性（score 1-5）
- 5: 可从 chunk/tile 回溯到 sample_id → source_id → URL
- 3: 可回溯但缺少 sample_id 中间环节
- 1: 无法回溯

**Cross-channel 通过**：3 项平均分 ≥3.0

---

## 五、成本与风险评估（权重 5%，不计入通过/失败但影响扩展决策）

| 评估项 | 可接受阈值 | 扩展风险 |
|--------|-----------|----------|
| 单页截图体积 | <5 MB | >10 MB 需压缩策略 |
| Tile 数量 | <20/page | >30/page 需评估索引膨胀 |
| 渲染耗时 | <10s/page | >30s/page 不适合批量 |
| 浏览器依赖 | 无头浏览器 OK | 如需 GUI 浏览器 → 高风险 |
| GPU/VLM 依赖 | 无 | 如需 VLM → 仅 on-demand |

---

## 六、综合判定

| 判定 | 条件 |
|------|------|
| ✅ **PASS** | 全部三维度平均分 ≥3.0，成本在可接受阈值内 |
| ⚠️ **PASS_WITH_LIMITATIONS** | Text 通过，Visual 或 Cross-channel 边缘（2.5-3.0） |
| ❌ **FAIL** | 任一维度 <2.5 或成本超出可接受阈值 |

FAIL 的样本不进入正式入库。PASS_WITH_LIMITATIONS 的样本可考虑仅在特定 query_type 下启用 visual sidecar。

---

## 七、后续扩展判定

如果 3 个样本中 **≥2 个 PASS**（含 PASS_WITH_LIMITATIONS），向 Phase 3F 推荐扩展 visual sidecar 到更多 URL。

如果 **0 个 PASS**，保持 visual_capture.enabled=false 作为默认设置。
